# Contributing

Thanks for your interest in contributing to this profile and associated projects. Please follow these guidelines to make collaboration smooth.

1. Reporting issues
   - Open an issue with a clear title and description, steps to reproduce, and expected behavior.
   - Tag the issue with labels if appropriate (bug, enhancement, question).

2. Proposing changes (pull requests)
   - Fork the repository and create a feature branch from `main`.
   - Keep changes small and focused; one logical change per PR.
   - Write clear commit messages and include tests when applicable.
   - Ensure the project builds and tests pass locally before submitting.

3. Code style and quality
   - Follow existing project style (PEP8 for Python, standard ESLint/Prettier for JS/TS).
   - Run linters and formatters before creating a PR.

4. Testing
   - Add unit or integration tests for new features and bug fixes where feasible.
   - Document how to run tests in the repository README.

5. Communication
   - Use PR descriptions to explain the why, not just the what.
   - Respond to review feedback and iterate on your PR.

If you need help getting started, open an issue and I'll assist.
